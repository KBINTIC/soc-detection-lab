Démarrage d'un audit de sécurité

Guide opérationnel — SOC Detection Lab & Kit d'audit client · audit non intrusif (lecture seule)

Ce guide explique comment démarrer un audit de sécurité des postes d'un client, sur site (clé USB) ou à distance (SSH), où se trouvent les fichiers du projet, les prérequis, et les informations à recueillir auprès du client. Principe constant : la machine exécute, l'humain décide — l'audit ne modifie rien ; les corrections sont validées en laboratoire avant toute application.

1. Où se trouvent les fichiers (SOC Detection Lab)

Tout le projet est dans un seul dépôt, sur le Mac : ~/Documents/soc-detection-lab/ (également publié sur github.com/KBINTIC/soc-detection-lab).

2. Prérequis

Sur ton Mac (poste consultant)

  • Python 3 (présent via Anaconda) — pour générer les rapports.
  • Google Chrome — pour l'export PDF du rapport (sinon : ouvrir le HTML et Cmd+P > Enregistrer en PDF).
  • Le dépôt ~/Documents/soc-detection-lab/ à jour.
  • Une clé USB en exFAT (lisible Windows et Mac) pour l'audit sur site.

Laboratoire de validation (déjà en place)

  • UTM + VM Windows et Wazuh sur Docker — pour tester les corrections et les détections avant le client.

Sur les postes du client

  • Compte administrateur local sur chaque poste à auditer (mot de passe admin).
  • PC Windows : rien à installer ; l'audit se lance depuis la clé en administrateur.
  • Mac : l'audit utilise python3 pour écrire son rapport. Présent sur la plupart des Mac ; sur un Mac neuf, la première exécution peut proposer d'installer les outils de développement (à accepter).
Autorisation obligatoire. N'auditez jamais un poste sans l'accord écrit du client (mandat d'audit précisant le périmètre et la date). L'audit est non intrusif, mais l'autorisation est une règle.

3. Informations à demander au client

À recueillir avant l'intervention (par téléphone ou e-mail), puis à confirmer sur place. Cette fiche sert aussi à dimensionner la mission et à renseigner l'en-tête du rapport.

Identité & autorisation

  • Raison sociale, adresse, contact technique (nom, téléphone, e-mail).
  • Autorisation écrite d'auditer (mandat) et périmètre convenu.
  • Personne à prévenir sur place le jour J ; horaires d'accès aux locaux.

Parc à auditer

  • Nombre de PC Windows et de Mac (et versions si connues).
  • Présence de serveurs (Windows Server, NAS) — hors périmètre poste, à cadrer à part.
  • Postes portables / télétravail (présents sur site ce jour-là ?).
  • Postes critiques à ne pas perturber (caisse, planning, dossiers patients…).

Accès (selon le mode d'audit)

ModeÀ demander
Sur site (clé USB) recommandé Accès physique aux postes ; mot de passe administrateur local de chaque poste (ou présence d'un référent qui le saisit) ; autorisation de brancher une clé USB.
À distance — Mac (SSH) Même réseau (ou VPN) ; Connexion à distance (SSH) activée sur le Mac (Réglages > Général > Partage) ; identifiant + mot de passe d'un compte admin ; adresse IP ou nom du Mac.
À distance — Windows Non couvert par SSH : utiliser la clé USB, ou WinRM/PSRemoting si le client l'a configuré (à cadrer).

Contexte sécurité (utile pour l'analyse et la suite)

  • Antivirus / EDR en place (p. ex. Bitdefender GravityZone) — conditionne le contrôle « temps réel ».
  • Domaine Active Directory / Entra ID ? MDM ? Microsoft 365 ? (pour Cockpit MS365).
  • Chiffrement (BitLocker / FileVault) et emplacement des clés de récupération — indispensable avant toute correction de chiffrement.
  • Existence de sauvegardes et date de la dernière restauration testée.
  • Contraintes RGPD / confidentialité ; données sensibles sur les postes.
  • Destinataire du rapport et format attendu (PDF).

4. Démarrer l'audit — sur site (clé USB)

  1. Préparer la clé (au bureau). Formate une clé en exFAT. Sur ton Mac, lance audit-client/Demarrer-Audit-Client.command, saisis le nom du client, puis choisis 1) Préparer la clé USB et indique le chemin de la clé (ex. /Volumes/AUDIT).
  2. Sur chaque poste du client (≈ 1 à 2 min, lecture seule) :
    • PC Windows : ouvre AuditKit\ sur la clé, clic droit sur Lancer-Audit-Windows.bat > Exécuter en tant qu'administrateur.
    • Mac : ouvre AuditKit/, double-clique audit-poste-mac.command (clic droit > Ouvrir la 1re fois), saisis le mot de passe admin.
    Chaque audit écrit un rapport JSON dans AuditKit/rapports/ sur la clé.
  3. De retour au bureau. Relance l'orchestrateur, choisis 4) Importer des rapports depuis une clé USB (chemin /Volumes/AUDIT/AuditKit/rapports).
  4. Générer le rapport. Choisis 5) Générer le rapport d'audit (PDF). Le rapport client s'ouvre : postes audités (PC / Mac), durée moyenne, conformité moyenne, écarts par poste, corrections proposées.

5. Démarrer l'audit — à distance (Mac, SSH)

  1. Le client active Connexion à distance (SSH) sur le Mac et te communique l'IP et un compte admin.
  2. Sur ton Mac, lance l'orchestrateur, saisis le client, puis 3) Auditer un Mac à distance (SSH) et entre utilisateur@ip.
  3. L'audit s'exécute à distance (mot de passe du poste demandé) et le rapport revient dans la mission.
  4. Choisis 5) Générer le rapport. Pour les PC Windows distants, privilégie la clé USB.

6. Après l'audit — corrections (étape distincte)

  1. En lab : pour chaque écart, valide la correction sur la VM — voir audit-client/CAHIER-VALIDATION-VM.md (commande + annulation), puis vérifie qu'aucun usage n'est cassé.
  2. Chez le client : applique les corrections validées avec hardening-toolkit/ (console ui/index.html ou scripts/02-Harden.ps1), avec validation O/N et rapport avant / après, chaque correction étant réversible.
Mémo rapide. Audit = audit-client/ (lecture seule). Correction = hardening-toolkit/ (après validation en lab). Détection/SIEM = lab/ + rules/.
