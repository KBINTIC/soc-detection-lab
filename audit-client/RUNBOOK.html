Mode opératoire — Mission d'audit de sécurité

Audit non intrusif (lecture seule) des postes du client, piloté depuis le Mac consultant. Principe : la machine exécute, l'humain décide. Aucune correction n'est appliquée pendant l'audit.

0 Avant le rendez-vous (au bureau)

  1. Double-cliquer sur Demarrer-Audit-Client.command.
  2. Saisir le nom du client → un dossier de mission daté est créé automatiquement.
  3. Choix 1 : brancher une clé USB et copier le kit d'audit dessus.
  4. Vérifier que la clé contient AuditKit/Lancer-Audit-Windows.bat et AuditKit/audit-poste-mac.command.

1 Sur site, en présence du client

  • Expliquer en une phrase : « L'audit est en lecture seule, il ne modifie rien ; il mesure l'état de sécurité de chaque poste et produit un rapport. »
  • Recenser les postes à auditer (PC / Mac). Chaque poste prend environ 30 à 60 secondes.
Deux méthodes au choix selon le poste : clé USB (toujours), ou audit à distance si tu es sur le même réseau et que l'accès est activé.

2 Auditer chaque poste

Poste Windows (clé USB)

  1. Brancher la clé, ouvrir AuditKit.
  2. Clic droit sur Lancer-Audit-Windows.bat → Exécuter ; accepter l'élévation administrateur.
  3. Attendre la fin (liste [OK]/[!!]). Le rapport JSON est écrit dans AuditKit/rapports.

Poste Mac (clé USB)

  1. Ouvrir le Terminal, puis : sudo bash /Volumes/<CLE>/AuditKit/audit-poste-mac.command "Nom du client"
  2. Saisir le mot de passe administrateur du poste. Le rapport JSON est écrit dans rapports.

Audit à distance (option, même réseau) — depuis le Mac consultant, choix 3 : indiquer utilisateur@ip du Mac client (Connexion à distance / SSH activée côté client). Pour un Windows distant, préférer la clé USB.

Rien n'est modifié sur les postes : tous les contrôles sont en lecture seule.

3 Rapport d'audit (avant correction)

  1. Rapatrier les rapports : clé USB → choix 4 (importer depuis la clé) ; audit distant → déjà dans la mission.
  2. Choix 5 : génération du rapport PDF à ton en-tête, avec nombre de postes (PC/Mac), conformité moyenne, écarts et durée moyenne par poste.
  3. Présenter / remettre le PDF au client. Il liste aussi les corrections proposées.

4 Validation en lab AVANT toute correction

De retour au bureau, chaque correction proposée est d'abord testée sur la VM de lab (jamais directement chez le client) avec la suite de durcissement hardening-toolkit :

cd hardening-toolkit\scripts
.\01-Audit.ps1                 # état de la VM
.\02-Harden.ps1 -WhatIf        # montre ce qui serait fait, sans rien changer
.\02-Harden.ps1                # applique après validation (O/N par contrôle)
.\01-Audit.ps1 -Phase apres
.\03-Report.ps1                # rapport avant/après de la VM

Les commandes à valider correspondent aux identifiants du rapport d'audit :

IDVérifier sur la VM que la correction…
LLMNR-001désactive bien LLMNR sans casser la résolution DNS interne.
NTLM-001passe NTLMv2 (niveau 5) sans bloquer un vieux périphérique réseau (NAS, imprimante).
SMB-001désactive SMBv1 sans couper un partage legacy encore utilisé.
RDP-001force NLA sans empêcher un accès distant légitime.
PSLOG-001 / AUDIT-001active la journalisation attendue (visible dans l'observateur d'événements).
BITLOCKER-001 / FV-001reste manuelle : activation du chiffrement + sauvegarde de la clé de récupération.
Chaque correction est réversible (99-Undo.ps1). On ne planifie l'application chez le client qu'une fois la correction validée en lab.

5 Application chez le client & rapport après

  • Appliquer, poste par poste, uniquement les corrections validées, avec l'accord du client.
  • Relancer un audit → générer un rapport après pour mesurer le gain de conformité.

✓ Check-list rapide sur site

  • Clé USB avec le kit préparée
  • Client informé (audit lecture seule)
  • Chaque poste audité (PC + Mac)
  • Rapports rapatriés dans la mission
  • Rapport PDF généré et présenté
  • Corrections à valider en lab avant toute application
